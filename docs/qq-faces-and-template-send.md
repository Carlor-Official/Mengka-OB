# QQ 表情显示与模板发送修复

聊天记录按 `faceType`、`faceId` 以及扩展名称识别内置 QQ 表情。小表情采用与 NT 早期聊天界面一致的 26px 行内尺寸，已知大表情采用 112px，并在可用时显示 APNG；减少动态效果设置下使用静态图。Markdown、引用和合并转发中的表情使用相同映射。未知自定义表情仅有名称、没有可识别编号或附件地址时保留名称，不伪造资源。

资源索引参考 koishijs/QFace 的固定提交 `c96fa14ff894147ac0442dda0fce6a4523e5fcbd`，当前覆盖 327 个具有静态图片的数字 QQ 表情编号。运行时仅从索引固定的腾讯 `wa.qq.com` 资源包读取指定 PNG/APNG 条目，通过已认证的同源接口提供图片。单个资源限制 8 MiB、资源包限制 16 MiB，并发下载上限为 2，独立缓存上限为 128 MiB。图像版权属于腾讯；索引来源说明和项目许可随前端附带。

聊天管理发送消息模板前会构造规范的消息体：

- 仅有正文和按钮的旧文本模板转为 `msg_type: 2` 与 `markdown.content`，保留按钮。
- 简写 `keyboard.rows` 包装为 `keyboard.content.rows`，错误结构在发送前提示。
- 原生 Markdown 模板可用输入框正文覆盖模板正文；留空使用模板内容。
- 官方 `custom_template_id` 模板保持 ID 与参数，不接受会被忽略的额外正文；前端提示去消息模板中修改参数。
- 主动发送和无权限后的被动重试使用同一份规范化正文与按钮，沿用幂等请求标识；不改写已保存模板。

已验证模拟 QQ HTTP 接口收到 `msg_type: 2`、完整 `markdown.content` 与 `keyboard.content.rows`，发送日志与实际请求一致。未向真实 QQ 会话发送测试消息。真实客户端按钮展示仍受应用权限、按钮动作/权限配置及 QQ 客户端支持情况影响。
