# 萌卡OB 1.0.1beta

修复服务器部署后无法通过公网 IP＋端口访问的问题。

- 默认监听所有网卡的 TCP 18080，与 NT 默认部署行为一致；初始化保存的端口在重启后继续监听所有网卡。
- 显式 `-listen` 仍优先，可限制为本机访问；新增 `MENGKA_OB_LISTEN_HOST`，只限制网卡而不覆盖保存端口。
- 完整安装包从其他目录启动时，也能找到程序旁的前端和数据；旧工作目录已有数据会保留，存在两份数据库时要求明确指定。
- 缺少前端文件时启动给出明确错误，避免空白页和错误目录下的新配置。
- 完善外网 IP、TCP 端口、云安全组、防火墙、systemd 后台运行和升级说明，修正初始化默认端口提示。

## 部署

完整解压后启动 `mengka-ob.exe` 或 Linux 的 `./mengka-ob`，服务器访问 `http://服务器公网IP:18080`。云安全组和系统防火墙都需要放行 TCP 18080，或你实际设置的端口。

管理页支持 IP＋端口；QQ 官方 Webhook 回调仍需公网 HTTPS。

旧 beta 暂不升级时，可先使用 `./mengka-ob -listen 0.0.0.0:18080`。如果自己的 systemd 或启动脚本仍写有 `-listen 127.0.0.1:18080`，新版会尊重该配置；需要公网直连时请调整它。

[完整部署与 systemd 指南](https://github.com/Carlor-Official/Mengka-OB/blob/main/docs/deployment.md)。

## 升级

先备份整个 `data` 目录。可通过框架在线更新，或停止程序后替换可执行文件与 `web/dist`，保留数据。请勿使用 NT 数据目录或让多个进程共用数据。

本次仍为内测版，继续使用与上一外发包一致的混淆、防调试信息泄露和签名授权校验；不修改生产最低版本门槛。Linux ARM64 包已交叉编译与架构检查，原生设备仍需内测反馈。

本次部署修正版统一版本名为 **1.0.1beta**，内部版本与标签为 `1.0.1-beta`。
