# 插件服务与导入

萌卡OB保留正向 WebSocket、反向 WebSocket、本机 IPC 和插件包导入。插件层重新设计为独立 `obp/1` 协议，并非直接兼容旧框架。

- 正向 WS：插件连接框架的 `/plugin/ws/{serviceID}`。
- 反向 WS：框架连接插件提供的 WS/WSS 端点。
- 本机 IPC：框架启动插件进程，通过 stdin/stdout 双向消息管道通信。
- 插件导入：验证新清单、平台入口与文件路径，保存后再创建服务。导入本身不执行程序。

三种模式统一使用服务令牌，按 Bot、接口和事件明确授权；未授权的能力默认关闭。修改权限前先停止服务。本机插件具有当前操作系统账号的权限，启动前需确认信任包来源。

详细消息与清单规范见 [插件协议](plugin-protocol.md)。可编译的 [IPC 示例插件](../examples/ipc-echo/) 展示握手、事件确认和官方消息调用。

Node.js、Python 和 Go 都可开发新协议插件。旧 NT 托管包、OneBot 插件和官机云 Python 插件不能原样导入后自动适配，需要重新实现通信和权限契约。

已有内置 Ping 与指令规则仍保留在“内置插件”子页，不替代主插件系统。

## 云平台插件移植

0.4.0-dev 已将额度监控、应用登录、哔哩套件、官机管理、指令回复、GitHub 版本订阅、日志记录、网页登录、欢迎消息及 X 推文订阅移植为独立 IPC 包。移植包使用原生 OBP 通信与每 Bot 数据目录，不安装旧网页补丁、不读取旧平台生产数据。源码及开发 ZIP 仍在私有开发环境维护，当前没有发布正式下载包。

Python 插件需要 Python 3.11 或以上及包内 `requirements.txt` 的依赖。导入后创建服务，配置 Bot、事件和接口权限；配置示例会自动填入编辑器。网页与图片功能还需配置指向本实例的 HTTPS `public_base_url`，反向代理须转发 `/plugin-ui/`、`/plugin-media/`、`/webhooks/official/`。

网页登录和应用登录只面向管理员明确配置的 `console_admin_ids`，需要单独授予 `issue_login_ticket`。私聊签发的凭据 5 分钟有效且只能使用一次，可在原版登录页的密码栏填写。官机管理的 `registry_manage` 可管理所有 Bot，应只授予可信服务。哔哩套件保留原有授权校验，并通过 `bots.AppID.uin` 配置机器人 QQ。

本地测试覆盖实际进程启动、双 Bot 回放与去重，但没有替代真实官方 Bot、外部供应商凭据及生产推送验证。旧平台账号与订阅不会自动迁入。
