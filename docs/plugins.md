# 插件服务与导入

萌卡OB保留正向 WebSocket、反向 WebSocket、本机 IPC 和插件包导入。插件层重新设计为独立 `obp/1` 协议，并非直接兼容旧框架。

- 正向 WS：插件连接框架的 `/plugin/ws/{serviceID}`。
- 反向 WS：框架连接插件提供的 WS/WSS 端点。
- 本机 IPC：框架启动插件进程，通过 stdin/stdout 双向消息管道通信。
- 插件导入：验证新清单、平台入口与文件路径，保存后再创建服务。导入本身不执行程序。

三种模式统一使用服务令牌，按 Bot、接口和事件明确授权；未授权的能力默认关闭。修改权限或配置前先暂停或停止服务。本机插件具有当前操作系统账号的权限，启动前需确认信任包来源。

详细消息与清单规范见 [插件协议](plugin-protocol.md)。可编译的 [IPC 示例插件](../examples/ipc-echo/) 展示握手、事件确认和官方消息调用。

Node.js、Python 和 Go 都可开发新协议插件。旧 NT 托管包、OneBot 插件和官机云 Python 插件不能原样导入后自动适配，需要重新实现通信和权限契约。

旧“内置插件”和“指令规则”页面跳转到账号列表。指令规则已并入账号消息设置，不再要求启用插件。

## 云平台插件移植

业务插件与框架分开交付。框架提供连接、授权、事件持久化与分发、日志和会话权限等通用能力；订阅、推送、指令回复、欢迎内容和业务登录流程由对应插件实现。旧的账号内置路径仅作为兼容方式保留；选择 IPC 处理业务的账号不应再同时执行同一套内置业务。

**1.0.7-beta 安装包不包含任何预配置机器人、业务插件包或插件数据。** 插件需要使用者单独导入并授权，旧平台账号和订阅不会自动迁入。

Python 插件需要 Python 3.11 或以上及包内 `requirements.txt` 的依赖。导入后创建服务，配置 Bot、事件和接口权限；配置示例会自动填入编辑器。网页与图片功能还需配置指向本实例的 HTTPS `public_base_url`，反向代理须转发 `/plugin-ui/`、`/plugin-media/`、`/webhooks/official/`。

应用登录插件使用 `console_admin_ids` 与 `issue_login_ticket` 权限；使用旧兼容模式的账号仍可在“登录授权”中配置；使用独立网页登录插件时，可通过 `login_scope: "bot"` 签发仅限指定机器人的会话。私聊签发的凭据 5 分钟有效且只能使用一次，可在原版登录页的密码栏填写。官机管理的 `registry_manage` 可管理所有 Bot，应只授予可信服务。哔哩套件保留原有授权校验，并通过 `bots.AppID.uin` 配置机器人 QQ。

本地测试覆盖实际进程启动、双 Bot 回放与去重，但没有替代真实官方 Bot、外部供应商凭据及生产推送验证。旧平台账号与订阅不会自动迁入。


## 暂停与恢复

服务卡片固定按名称排序，轮询只更新状态。可按插件名称、机器人名称或 AppID 搜索。

“暂停执行”保留服务启用状态并继续持久化收件，插件进程或连接暂停；可编辑配置后选择“恢复执行”处理积压。“停止服务”位于更多菜单中，停止期间不接收新投递。令牌重置和删除仍需先停止。

默认事件模式是独立接收；需要按顺序执行业务的服务可使用 handler 模式、优先级和 consumed 确认，详见协议。只授予插件实际需要的账号、接口和事件权限。
