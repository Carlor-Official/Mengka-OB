# 消息按钮与图片缓存修复

本改动涉及前后端，需要完整升级；仅替换 `web/dist` 无法启用图片缓存。

## Markdown 消息按钮

按 `keyboard.content.rows` 的原始行列显示按钮，兼容已有记录中的 `keyboard.rows` 和 JSON 字符串。保留标签、灰色/蓝色描边、等宽行内排列及 Windows QQ 的紧凑间距。窄屏保持行列并允许文字换行；触摸设备增加点击区域。

链接按钮仅允许 HTTP/HTTPS 跳转。指令和回调按钮保留外观并提示在 QQ 客户端操作，不从 OB 冒充消息接收者执行。只有模板 ID、没有按钮内容时明确说明，不能凭空还原模板。格式依据[QQ 消息交互说明](https://bot.q.qq.com/wiki/develop/api-v2/server-inter/message/trans/overview.html)。

## 图片为何失效

已验证用户提供的 QQ 图片 URL 返回 HTTP 400，`retcode=-5503007`，`retmsg=download url has expired`。这类临时地址不能通过反复重试恢复。已过期且未缓存的旧图需要重新发送；框架不会伪造 rkey 或借用其他图片的密钥。

框架在记录新消息后，异步缓存已知 QQ 图片域名的附件、Markdown 图片和合并转发图片。每条消息最多预取 32 张，两个工作任务并行，最近十分钟的待处理图片最多自动尝试三次；消息处理本身不等待下载。其他公网图片在管理员查看时缓存。

前端通过同源、需要登录的图片接口读取，普通图片和 Markdown 图片均优先使用本地副本。图片 URL 必须属于当前 Bot 的对应消息，不能把接口作为任意 URL 代理。撤回后拒绝读取；跳转及 DNS 连接禁止内网、回环和保留地址，不携带 QQ 授权头或管理员 Cookie 到源站。Fake-IP DNS 会被明确提示为非公网解析，需要检查部署服务器的 DNS/代理配置。

缓存来源地址和图片内容分别加密，单图上限 16 MiB，图片数据总预算 256 MiB，按最近使用情况淘汰，最长跟随消息保留 30 天。缓存不等于永久图库。收到同一 QQ 文件的新签名 URL 时可更新其缓存来源，原始事件不被修改。

接口：`GET /api/v1/accounts/{appid}/console/chat/image/{journal_id}?url=...`。已过期且无缓存返回 410，并通过 `X-OB-Image-Error: expired` 给出明确原因；403、404、格式不支持、大小超限和网络失败分别报告。

测试覆盖：源站过期响应、浏览器可用图片格式、源站失效后读取缓存、后台预取及失败重试、Bot/消息隔离、未登录与撤回访问拒绝、原文保留、按钮行列与不安全链接、手机宽度及明暗样式。未发送真实 QQ 测试消息。
