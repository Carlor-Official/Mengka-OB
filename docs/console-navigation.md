# 官机云功能入口与萌卡 OB 控制台

0.6.0-dev 将官机云的功能组织方式接入萌卡 OB，同时保留 NT v2.6.0 的侧栏、组件、配色和按钮反馈。菜单统一四字，分组支持折叠、键盘操作、当前页面高亮与手机端“更多功能”。

| 分组 | 入口 |
| --- | --- |
| 数据面板 | 框架运行概况 |
| 机器管理 | 账号列表、消息模板、服务节点 |
| 数据管理 | 消息日志、群组管理、用户管理 |
| 运营管理 | 指令配置、欢迎配置、分享链接、任务配置、订阅管理 |
| 聊天管理 | 会话记录、发送消息、撤回本机发送记录 |
| 插件管理 | 插件导入、插件服务 |
| 系统设置 | 框架配置、接口调试、关于应用 |

所有新增页面都有独立路由，页面标签与左侧选中状态一致。管理页面按所选 Bot 隔离，切换页面沿用当前 Bot；分享链接、聊天和任务发送使用当前 Bot 的独立凭据。

## 数据和消息

消息模板保存完整的原生 Markdown、官方模板参数、按钮或媒体 JSON，可供指令、欢迎消息、聊天和定时任务引用。引用中的模板不能被直接删除。指令与欢迎配置是可直接编辑的页面，同时保留账号菜单中的快捷配置。

群组和用户从实际入站事件中发现，当前列表最多展示最近 1000 项；这不是从 QQ 拉取的完整通讯录。可以修改本地显示名称、备注、标签和启用状态。标签参与框架指令范围匹配；停用对象的入站事件仍记日志，但不触发自动回复或插件。

消息日志显示最近 100 条记录。聊天可选择会话、填写消息或引用模板，并使用已收到的消息 ID 进行回复。发送前确认目标和内容；没有启用 Bot 时不能发送。撤回使用实际官方返回的消息 ID，只允许操作本 Bot 的本机发送记录。撤回成功保留日志并标记“已撤回”，不删除审计记录。截图中的独立“开发中召回管理”未做空占位，而是通过聊天页的撤回操作实现。

## 分享、订阅和任务

分享链接通过官方 `/v2/generate_url_link` 接口生成，只有收到有效 HTTPS 链接才写入历史；失败不会显示虚构结果。回调数据重复时拒绝再次生成。删除本地历史不会撤销官方链接。

订阅管理对应官机云的 **QQ 官方消息订阅授权**，由 `SUBSCRIBE_MESSAGE_STATUS` 的授权事件登记；不会把手填 ID 当作授权。当前按参考平台处理 `op=1`，其他事件操作不猜测含义。停用订阅会阻止后续任务使用它。B站、X、GitHub Release 等业务订阅仍归各自插件管理。

定时任务选择官方授权订阅，使用其官方模板与参数；可保存周期、时区、启停状态，查看下次计划和最近结果，也可确认后手动执行。Cron 为五段“分 时 日 月 周”，默认新建时区为 Asia/Taipei，服务端按配置时区计算下次计划，解析由 [robfig/cron 官方库](https://github.com/robfig/cron)提供。

每次计划执行先持久化领取记录再发送，重复调度不重复提交同一次计划。框架停机期间错过的多个计划不集中补发，恢复后最多执行当前逾期计划，再计算未来时间。发送结果不确定或进程中断时显示“结果待核对”，不自动重发该次消息；以后独立的计划仍按周期处理。未启用 Bot、静默模式、订阅停用、模板不匹配均会阻止发送并留下执行结果。

## 验证与边界

本地测试覆盖分组导航、十个新增路由、桌面和手机布局、模板关联、用户标签、订阅启停、任务保存、Bot 隔离，以及通过模拟 QQ 服务完成分享、发送、撤回和调度。没有向真实 QQ 联系人发送测试消息。实际开放平台权限、额度、官方接口返回和真实账号操作仍需在连接有效 Bot 后验证。

存储使用框架自己的 SQLite 表，配置内容加密；没有修改官机云源码或连接其生产数据库。新版本首次启动自动建表，保留已有管理员和 Bot 配置。
