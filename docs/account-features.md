# 框架原生账号功能

从 0.5.0-dev 起，日志、网页登录、指令回复和欢迎消息是 Go 框架的一部分。它们没有插件包、服务令牌或 Python 进程，不需要导入、启动或授权 IPC 服务。它们的设置位于「账号列表 → 更多操作 → 消息设置」，消息记录位于「消息日志」。旧的内置插件/指令规则页面跳转到账号列表。

## 指令回复

每个 Bot 独立保存规则，按列表顺序匹配第一条：完全相同、包含关键词、指定开头、指定结尾和 Go RE2 正则。可限制群聊/私聊、用户或群 OpenID、用户标签或群组标签，范围条件与标签条件分别支持任一/全部满足。命中的框架指令不再投递给外部插件，避免多次回复。

回复支持文字、多条备选回复、Markdown/按钮/媒体原始消息 JSON，以及从指定 HTTP API 获取文字或 JSON 路径的值。JSON 消息中的文本逐字段替换，不把用户输入拼接到 JSON 结构里。可使用 `{user_id}`、`{user_name}`、`{user_uin}`、`{group_id}`、`{appid}`、`{msg}`、`{time}`、`{msg[0:5]}`、`{match[1]}`。机器人平台不提供 QQ 号时不猜测，`{uin}` 返回“未知”。

回复 API 支持 GET/POST、指定请求头/请求体和 `data.items[0].text` 形式的 JSON 路径。限时 10 秒、响应最多 1 MiB，消息变量不能改变请求主机或协议。API 返回值和发送结果使用加密的事件处理记录避免重复调用；提交结果不确定时不自动重复 POST。

## 欢迎消息

机器人入群与添加好友各自配置开关、内容和可选的 Markdown/按钮消息。发送使用官方事件的 `event_id`，同一事件重复投递不会重复发送。不需要单独的欢迎插件进程。

## 网页登录

账号消息设置中明确指定控制台管理员 OpenID，默认关闭。被授权用户私聊该 Bot 发送“后台登录”，框架验证实际事件来源、发送者和时间后签发五分钟有效的一次性凭据。使用现有控制台登录页的用户名和密码栏即可登录；群聊不会签发凭据。

这是整个控制台的管理员权限，不是单 Bot 主人权限。关闭功能、改变登录授权名单或修改管理员密码后，未使用凭据失效。凭据不进入消息日志或外部插件的发送事件。

## 日志与存储

收发日志由框架自动记录，默认保留 30 天，账号抽屉显示最近 100 条。记录按 Bot 隔离；重复入站事件不重复写日志，登录凭据自动隐藏。静默模式仍记录入站事件，但不会执行自动回复。

账号配置、回复 API 凭据和动作结果由框架加密保存，与 `master.key` 一起备份。删除 Bot 会通过外键清理其配置及消息记录。旧版本的四个 IPC 模块不再打包或执行；若数据目录存在旧服务，启动时停用并保留原配置、插件状态目录与包元数据供恢复。旧服务的复杂配置不会被静默转换或覆盖，应在账号消息设置中核对后配置。已有原生指令规则按账号原启用状态读取，保存新设置后以账号配置为准。

## API

- `GET/PUT /api/v1/accounts/{appid}/features`：读取/保存该账号的命令、欢迎和控制台登录设置。
- `GET /api/v1/accounts/{appid}/messages`：读取该账号最近消息记录。

以上接口都要求现有控制台管理员认证。剩余六个业务插件继续使用 OBP 的正向 WS、反向 WS 或 IPC，插件层与框架原生功能分开管理。
