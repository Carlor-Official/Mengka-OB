# 萌卡OB 算法系统接入（1.0.0-beta）

算法系统中的框架账号区分 **萌卡NT** 与 **萌卡OB**。产品类型 `framework_type` 与原有 free/plus 授权档位相互独立；类型在首次登记时绑定，不能通过后续请求切换。旧账号和旧 NT 请求继续归为 NT。

## 账号与心跳

初始化本地管理员后，OB 使用独立、持久化的安装 Ed25519 身份自动登记。登记包含用户名、bcrypt 密码校验值、凭据修订号、散列设备标识及框架类型/版本，不发送管理员明文密码。管理员凭据或框架版本变化时重新同步；正常运行每 60 秒进行签名心跳，不重复上传密码校验值。

心跳只上报在线数量，不上报 Bot 清单、AppSecret 或消息内容。安装私钥、返回的 UID/secret 和策略缓存在本地加密保存。请备份完整数据目录及 `master.key`，不要用 NT 的数据目录启动 OB。

框架设置新增“算法接入”，显示登记状态、OB 最低版本和最近验证时间，可主动刷新。原有本地管理员登录保持不变。

## 独立版本限制

NT 与 OB 分别保存开关、最低版本和发布仓库。迁移保留原 NT 设置，OB 初始策略关闭、最低版本为 `0.0.0`，发行仓库指向 `Carlor-Official/Mengka-OB`。

OB 的门禁只使用经过固定信任公钥验证的签名运行响应，并检查安装实例、产品类型、随机挑战和有效期；公开查询参数不能改变已绑定身份。策略过期、接入未就绪或授权被撤销时，暂停机器人连接、业务收发、事件投递和计划执行；已保存的账号启停配置不被改写。有效策略恢复后恢复原先已启用的机器人。

低于 OB 最低版本时，后端自动下载符合门槛的 OB 对应更新通道发行包、校验安装并重启，不受普通自动更新开关影响。管理页显示 NT 同款进度、失败重试与完成弹窗；业务门禁继续生效。支持签名远程重启并在新进程就绪后回执，只接受绑定 OB 安装的指令。详见 [更新与重启](runtime-update.md)。

## 升级顺序

先部署支持双产品类型和签名运行接口的算法服务，再启用 1.0.0-beta OB 后端。旧算法服务不支持新登记字段或运行接口时，OB 将等待授权，不会把 NT 公开策略当成替代授权。升级前备份数据目录；此版本不修改生产最低版本值，也不发布 NT 正式版。

0.8.0 之前的 OB 尚未接入该管理链路，需要先升级，后台设置不会让未接入的旧程序自动升级或停机。安装签名证明密钥持有权，不是二进制远程证明。

管理 API：

- `GET /api/v1/system/framework-access`：管理员读取接入状态，不返回身份密钥或登记凭据。
- `POST /api/v1/system/framework-access/refresh`：管理员主动重新登记/验证，已有会话和同源校验继续生效。
- `GET /api/v1/open/framework-version-policy`：供更新页面展示已验证的 OB 策略，传入其他框架类型也不会改变结果。

## 验证

已验证签名登记、凭据 revision、心跳、加密持久化、跨产品/跨实例/重放/过期响应拒绝、最低版本限制、恢复原账号状态及本地管理登录。使用实际算法服务和独立测试数据库完成了真实 OB 二进制联调，确认 NT/OB 门槛互不影响；测试门槛已恢复。生产部署状态需单独核对。

浏览器验收必须使用独立算法服务，避免把测试管理员登记到生产。签名夹具运行方式：

```sh
node scripts/with-algorithm-fixture.mjs scripts/verify-framework-access.mjs
node scripts/with-algorithm-fixture.mjs scripts/verify-ui.mjs
```

夹具使用专门的测试公钥构建临时二进制，不改变正式构建内置的算法系统公钥。实际服务联调由 `scripts/verify-algorithm-integration.mjs` 执行，仅接受本机测试地址和私密的临时管理员凭据文件。
